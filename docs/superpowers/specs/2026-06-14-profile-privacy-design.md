# Приватность профиля: видимость избранного, просмотров и оценок

**Дата:** 2026-06-14
**Проект:** Aniyume (aniyume-api, Laravel)
**Автор:** Жаншугуров Т.Р.

## Цель

Дать пользователю контроль над тем, кто видит его активность на профиле:
**избранное (лайки)**, **просмотры (история)** и **оценки**. Друзья (или все,
или никто) могут открыть эти списки на чужом профиле. Управление — в настройках,
**отдельным тумблером на каждый из трёх разделов**.

## Текущее состояние (исходная точка)

- `GET /users/{userId}/profile` (`FriendshipController::profile`) уже отдаёт чужой
  профиль любому авторизованному пользователю — без проверки дружбы и без
  приватности. Возвращает `counts` (число избранного/оценок/друзей и т.д.), но
  **не сами списки**.
- Списки избранного (`GET /favorites`, `FavoritesController::index`),
  истории просмотров и оценок доступны **только владельцу** (`$request->user()`).
- У `users` нет полей приватности. `Setting` — это глобальные админ-настройки,
  не пользовательские.

## Решения по объёму

1. **Уровни видимости:** 3 значения — `everyone`, `friends`, `nobody`.
2. **Разделы:** три независимые настройки — избранное, история просмотров, оценки.
3. **Хранение:** три явные строковые колонки в `users` (вариант A). Дефолт —
   `friends`. Причина: значения фиксированы, query по ним не делается, явные
   колонки читаемы и сразу видны в существующей админке пользователей.
4. **Гейтятся только списки.** Агрегатные счётчики (`counts`) на карточке профиля
   остаются публичными как сейчас — приватность скрывает содержимое списков, а не
   цифры. Это минимально ломает текущее поведение карточки.

## Модель данных

Миграция добавляет в `users`:

| Колонка | Тип | Default |
|---|---|---|
| `privacy_favorites` | string | `'friends'` |
| `privacy_watch_history` | string | `'friends'` |
| `privacy_ratings` | string | `'friends'` |

- В `User`: добавить три поля в `$fillable`.
- PHP-enum `App\Enums\ProfileVisibility`: `Everyone = 'everyone'`,
  `Friends = 'friends'`, `Nobody = 'nobody'`.

## Сервис доступа

`App\Services\ProfileVisibilityService` — единственная точка авторизации:

```
canView(?User $viewer, User $owner, string $section): bool
```

Логика:
- `$viewer` === `$owner` → `true` (владелец всегда видит своё);
- иначе берём настройку владельца для секции:
  - `everyone` → `true`;
  - `friends` → `true`, только если между `$viewer` и `$owner` есть дружба
    со статусом `accepted` (в любую сторону);
  - `nobody` → `false`;
- `$viewer === null` (гость) видит только секции с уровнем `everyone`.

`$section` — одно из: `favorites`, `watch_history`, `ratings`. Сервис мапит
секцию на колонку владельца.

## API

### Просмотр чужих разделов (с гейтом)

| Метод | Маршрут | Отдаёт |
|---|---|---|
| GET | `/users/{userId}/favorites` | список избранного пользователя |
| GET | `/users/{userId}/watch-history` | недавние просмотры пользователя |
| GET | `/users/{userId}/ratings` | оценки пользователя |

- Доступ проверяется через `ProfileVisibilityService::canView`.
- Если запрещено → HTTP `403`, тело `{ "message": "...", "reason": "private" }`.
  Фронт по `reason=private` рисует состояние «скрыто».
- Пагинация и формат элементов — как в существующих self-эндпоинтах.
- Реализация переиспользует имеющуюся логику. Для избранного:
  `FavoritesController::index` рефакторится в общий приватный билдер
  `favoritesQuery(int $userId)`, который зовут и self-метод, и новый по `userId`.

### Свои настройки приватности

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/profile/me/privacy` | вернуть текущие 3 значения |
| PUT | `/profile/me/privacy` | обновить |

Валидация PUT: каждое поле (`favorites`, `watch_history`, `ratings`) —
`required|in:everyone,friends,nobody`. Недопустимое значение → `422`.

### Обогащение карточки профиля

В существующий `GET /users/{userId}/profile` добавляется блок `visibility`,
рассчитанный сервисом для **текущего зрителя**:

```json
"visibility": {
  "favorites": "visible",
  "watch_history": "hidden",
  "ratings": "visible"
}
```

`visible` если `canView` вернул `true`, иначе `hidden`. Фронт по этому блоку
решает, показывать ли кнопку «открыть список».

## Тестирование (Feature-тесты Laravel)

- `ProfileVisibilityService`: матрица владелец / друг / чужой / гость
  × `everyone | friends | nobody` для каждой из трёх секций.
- `GET /users/{id}/favorites|watch-history|ratings`: `200` для разрешённого
  зрителя, `403` с `reason=private` для запрещённого.
- `PUT /profile/me/privacy`: успешное сохранение; `422` на недопустимом значении.
- `GET /users/{id}/profile`: корректный блок `visibility` под разных зрителей
  (владелец, друг, чужой).

## Вне объёма этой спецификации (отдельные задачи)

- **Фронтенд (aniyume-web):** UI настроек приватности (3 тумблера) и кнопки
  «показать список» на чужом профиле. Контракт для фронта зафиксирован выше:
  3 значения, блок `visibility`, `403 reason=private`. Диплом по теме «Backend» —
  приоритет на API.
- Скрытие самих счётчиков (`counts`) — не делаем; при необходимости добавим позже.
